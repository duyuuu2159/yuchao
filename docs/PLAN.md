# 鱼巢（AgentNest）· 项目计划

> 一个本地优先的桌面工作台，把 Claude Code、Codex 等多个 AI agent 的会话、配置和「它们眼中的你」管在一起。
> 作者：杜瑜 · 计划日期：2026-11-07

## 1. 要解决的问题

重度使用多个 AI agent 时会遇到这些问题，作者本机上全都出现过：

| 问题 | 本机上的真实情况 |
|---|---|
| 会话散落、搜不到 | Claude 有 63 个会话文件（511 MB），Codex 有约 800 MB 会话，格式各不相同，部分是 zstd 压缩 |
| 每个 agent 都不认识你 | 换一个 agent 就要从头介绍自己、介绍服务器、介绍项目约束 |
| 配置容易坏 | Codex 的 `config.toml` 积累了 20 多个手工备份，出现过 `config.toml.corrupted` |
| 敏感信息泄露 | 服务器密码以明文出现在会话标题里 |
| 多 agent 同时操作一台服务器 | 并发部署互相覆盖，基线失效 |

## 2. 功能与里程碑

每个里程碑结束时都要是**能用、有测试、有 commit 记录**的状态，不留半成品。

### M1 · 统一会话库（已完成 2026-11-09）
- 读取 `~/.claude/projects/**/*.jsonl` 和 `~/.codex/sessions/**/*.jsonl(.zst)`
- 统一成一种数据模型：会话 → 消息 → 工具调用
- 增量索引到本地 SQLite（FTS5 trigram，支持中文搜索），只处理新增或变化的文件
- 命令行：`yuchao index`、`yuchao search "nginx 回滚"`
- 本地网页界面：会话列表、按 agent / 项目 / 时间筛选、全文搜索、查看会话详情

### M2 · 安全扫描（已完成 2026-11-09）
- 用规则加熵值检测出明文密码、API key、私钥、服务器地址加密码组合
- 生成报告：出现在哪个会话、哪一行、什么时间，结果里只显示打码后的内容
- **只读不改**：不修改 agent 自己的文件，只告诉你哪里有问题、应该怎么处理

### M3 · Agent 眼中的你（画像）（已完成 2026-11-09）
- 会话先经过 M2 的脱敏，再交给大模型提炼：技能、项目、偏好、常踩的坑
- 每一条结论都附带出处（链接到原会话），不允许没有依据的描述
- 画像有版本，可以看到随时间的变化；按 agent 分别生成，并排对比
- 导出为 `CLAUDE.md` / `AGENTS.md` 片段，同步给各个 agent 当共享记忆

### M4 · 配置管家（已完成 2026-11-09）
- 追踪 `~/.codex/config.toml`、`~/.claude/settings.json` 等配置的变更历史
- 修改前自动备份，可以查看差异、一键回滚
- 默认只读，写入操作必须由用户确认

### 扩展 · 接入更多 agent（已完成 2026-11-09）
- 把解析层改成适配器注册表，接入一个 agent = 写一个解析器 + 注册一项
- 已接入 WorkBuddy、DeepSeek Harness；OpenCode、Gemini CLI 等待本机有真实数据后再接（不凭文档猜格式）

### M5 · 桌面应用与服务器面板（已完成 2026-11-09）
- 用 Node 自带的单文件可执行程序（SEA）打包成 `yuchao.exe`，双击即用
- 服务器面板：服务状态、线上版本、发布记录、磁盘、异常退出和错误日志
- 按用户的选择只做只读：专用密钥在服务器上被锁定为只能运行状态脚本。回滚和部署锁没有做，需要时再单独评估

### M6 · 开源发布
- 发布到 GitHub：README 配截图和动图、CI 自动测试、Release 安装包、更新日志

## 3. 技术方案

| 层 | 选择 | 理由 |
|---|---|---|
| 语言 | TypeScript | 前后端统一，类型检查减少低级错误 |
| 运行时 | Node.js 24 | 自带 `node:sqlite` 和 zstd 解压，核心部分零原生依赖 |
| 存储 | SQLite + FTS5 trigram | 单文件、离线、中文搜索可用（已在本机验证） |
| 界面 | React + Vite | 生态成熟 |
| 桌面壳 | M5 时在 Electron 和 Tauri 之间选 | 先确认它们打包的 Node 版本是否满足需求 |
| 大模型 | 可配置（Claude / DeepSeek 等） | 不绑定单一服务商 |
| 测试 | `node:test` + 脱敏后的样例会话作为 fixture | 解析器最容易因为格式升级而出错，必须有测试保护 |

结构：

```
yuchao/
  src/
    core/      解析器、索引、扫描、画像（纯逻辑，不依赖界面）
    cli/       命令行入口
    server/    本地 HTTP API（只监听 127.0.0.1）
  web/         React 界面
  test/        测试，fixtures/ 是手写的样例会话
  docs/        计划、设计记录、开发日志
```

（最初计划拆成多个包，M1 时改成一个包里分目录：现阶段只有一个人开发，多包只会增加配置成本。）

## 4. 原则

- **本地优先**：所有数据留在本机；只有生成画像时，脱敏后的内容才会发给用户自己选择的大模型
- **只读优先**：不修改任何 agent 的文件，写配置的操作必须备份并经过确认
- **有出处**：画像里的每句话都能追溯到原始会话

## 5. 怎样才算「货真价实」

能写进简历的项目，面试官会追问细节。所以除了代码，还要有这些：

1. **真实的 git 历史**：每完成一个小功能就提交一次，commit 信息由作者自己写
2. **作者能讲清楚**：每个里程碑结束后，作者要能不看代码讲出：数据怎么流动、为什么这样设计、遇到了什么问题
3. **开发日志**（`docs/devlog.md`）：记录每个决定和踩过的坑，面试时就是现成的素材
4. **测试和 CI**：证明它不是只能在作者电脑上跑起来的 demo
5. **真实用户**：开源后有人用、提 issue，比任何自我描述都有说服力

## 6. 简历写法（M3 完成后可用）

> **鱼巢 AgentNest** — 多 AI agent 本地工作台（TypeScript / Node.js / SQLite / React）· 独立开发 · 开源
> - 设计 agent 适配器层，解析 Claude Code、Codex、WorkBuddy、DeepSeek Harness 四种会话格式（含按 RFC 8878 逐帧切分的多帧 zstd），统一索引 2 GB、251 个会话文件、6.2 万条消息，基于 SQLite FTS5 实现中文全文检索，增量更新约 6 秒
> - 设计敏感信息扫描器（规则 + 信息熵 + 指纹去重），在本人 4 个 agent 的 6.2 万条消息中发现 83 个泄露的密码和密钥（74 个高危，其中 60 个是 API key），一个服务器密码散布在 27 个会话里；全量扫描 2 秒
> - 用两步式大模型流程（逐会话总结 → 汇总）从 75 个会话提炼用户画像，每条结论附带出处，程序自动剔除模型编造的引用；同时支持 Claude 官方接口和 OpenAI 兼容接口
> - 打包为免安装的单文件程序（Node SEA + esbuild）；实现只读服务器面板，专用 SSH 密钥在 authorized_keys 中用 restrict + command 锁定到只读状态脚本，实测无法执行其他命令、转发端口或打开终端；接入当天即发现磁盘占用 86% 和 7 天内 22 次服务异常退出
> - 实现配置版本管理：把 31 个散落的手工备份整理成时间线，识别出 3 个内容全为空字节的损坏备份；回滚前自动备份并校验格式，用临时文件加原子替换避免写坏配置

（N 和其他数字以实际结果为准，不写没有做到的事。）
